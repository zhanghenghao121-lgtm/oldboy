# Oldboy 开发文档

## 1. 项目目标
实现微信小程序招聘聚合最小闭环：
1. 岗位搜索
2. 岗位详情
3. JD 技能分析
4. 可部署的后端与联调前端骨架

## 2. 功能点设计原理

### 2.1 岗位搜索（`/api/v1/jobs/search`）
- 原理：采用“适配器 + 标准化字段”模式，把不同来源的数据统一成一个稳定输出结构。
- 价值：新增来源时只需新增适配器，不影响 API 层。
- 细节：
  - 搜索参数先做序列化校验。
  - 按请求参数生成缓存键，缓存 5 分钟，减少重复查询。
  - 标准化结果写入 `JobNormalized` 表，支持后续详情/分析复用。

### 2.2 岗位详情（`/api/v1/jobs/{job_id}`）
- 原理：详情读取标准化表，不依赖前端反查第三方。
- 价值：接口稳定、响应快、可审计。

### 2.3 技能分析（`/api/v1/jobs/{job_id}/analyze`）
- 原理：
  - 优先使用模型 API（可配置 `MODEL_API_BASE + MODEL_API_KEY + MODEL_NAME`）。
  - 无可用模型配置时自动回退到本地启发式分析，保证联调不阻塞。
  - 结果按 `job_id + JD更新时间` 生成缓存键，复用分析结果。
- 价值：降低模型调用成本并提升接口稳定性。

### 2.4 数据源适配器机制
- 接口约定：`search -> detail -> normalize`
- 当前实现：`MockRecruitmentAdapter`（联调数据源）
- 扩展方式：新增适配器后注册到 `ADAPTERS` 列表即可参与聚合。

## 3. 技术栈

### 3.1 后端
- Python 3.12
- Django 5 + Django REST Framework
- MariaDB（生产）/SQLite（本地快速启动）
- Redis（缓存）
- Gunicorn（WSGI）

### 3.2 部署
- Docker Compose（`mariadb + redis + backend + nginx`）
- Nginx 反向代理 HTTPS

### 3.3 小程序端
- uni-app（Vue3）
- Pinia（已预置，可扩展状态管理）
- 页面：搜索页、详情页、分析页

## 5. 运行方式

### 5.1 本地后端
```bash
cd backend
cp .env.example .env
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver 0.0.0.0:8000
```

### 5.2 Docker 部署
```bash
cd deploy
cp env/prod.env.example env/prod.env
# 修改 prod.env 中密钥
docker compose --env-file env/prod.env up -d --build
```

### 5.3 小程序联调
```bash
cd apps/miniapp-uni
npm i
npm run dev:mp-weixin
```

## 6. 需要你人工协助的事项
1. 提供并配置真实招聘数据源（官方/合规 API）参数。
2. 提供可用模型网关地址并确认接口协议（当前按 OpenAI 兼容 `/chat/completions` 处理）。
3. 在微信公众平台配置 request 合法域名。
4. 服务器上放置 SSL 证书：`/etc/nginx/ssl/fullchain.pem` 与 `/etc/nginx/ssl/privkey.pem`。

## 7. 后续扩展建议
1. 增加用户鉴权与搜索历史。
2. 将分析接口改为异步任务队列（Celery + Redis）。
3. 增加多来源去重策略与排序打分。
4. 加入接口限流与审计日志。
